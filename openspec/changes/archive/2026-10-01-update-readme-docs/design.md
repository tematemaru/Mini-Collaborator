# Design

## Context

`Readme.md` — единственный источник документации проекта (мотивация — в `proposal.md`). Сервис небольшой: FastAPI-приложение в `app/main.py`, конфигурация через окружение в `app/config.py`, SQLite через SQLAlchemy, запуск точечно (`run.py`, `Dockerfile`) или через uvicorn. Актуальное поведение уже зафиксировано в capability-спеках `openspec/specs/`, что снимает необходимость выводить описания эндпоинтов заново — источником истины для текста остаётся код.

Ограничения: документация ведётся на двух языках; правила оформления заданы в требованиях `specs/project-documentation/spec.md`.

## Goals / Non-Goals

**Goals:**
- Выбрать раскладку документации, при которой её легко читать и поддерживать
- Зафиксировать способ двуязычного оформления без дублирования всего текста дважды
- Определить источник истины для фактов, чтобы текст не расходился с кодом

**Non-Goals:**
- Изменение кода, конфигурации, эндпоинтов и зависимостей
- Вынос части документации в отдельные файлы и каталоги
- Генерация документации из кода (Swagger/OpenAPI-экспорт)

## Decisions

**1. Всё в одном файле `Readme.md`.**
Единственная альтернатива — разделение на `docs/api.md`, `docs/deployment.md` и т.п. Отклонена: у сервиса семь операций и около 200 строк кода, отдельные файлы дали бы больше накладных расходов на навигацию, чем пользы, и потребовали бы ссылок друг на друга, которые придётся поддерживать. Если объём документации вырастет до уровня, при котором `Readme.md` станет нечитаемым, разделение можно выполнить позже без изменения требований — они сформулированы в терминах содержимого `Readme.md`, а не числа файлов.

**2. Основной текст — английский, ключевые разделы — с русскими дублями.**
Выбран вариант, при котором каждый ключевой раздел (Quick Start, Environment Variables, API Reference, Troubleshooting) содержит английское изложение и русское пояснение под ним, а второстепенные разделы (Features, Project Structure) остаются на английском с краткими русскими аннотациями.
Альтернативы: (а) полностью русский документ — отклонена, англоязычная аудитория не обслуживается; (б) полный дубль на двух языках — отклонена, файл раздувается вдвое и расходится при правках; (в) только английский — отклонена, не соответствует выбранному двуязычному формату.
Дубли реализуются блоками, а не ссылками, чтобы ключевой раздел оставался читаемым автономно.

**3. Факты берутся из запущенного сервиса, спорные quirks документируются как есть.**
Каждое утверждение о поведении сверяется с `app/main.py`, `app/config.py`, `.env.sample` **и проверяется фактическим запуском сервиса**. Последняя проверка обязательна: часть заявленных в коде кодов ответа не достигается. FastAPI 0.104.1 не разбирает возврат кортежа `(body, status_code)`, поэтому ветки `return {"error": ...}, 404` в `GET /stats/{token}` и `return {"error": str(e)}, 500` в `/c/{token}` формируют HTTP 200 с телом-массивом `[{"error": ...}, 404]` и `[{"error": ...}, 500]`. Документация описывает именно это: HTTP-статус 200, числовой код внутри тела.
Также описываются фактически, без нормализации и без пометок «это баг»: невалидируемый токен на `/c/{token}`, 200 с пустым массивом вместо 404 на `/logs/{token}`, `recent` в `/stats/{token}` как последние 10 строк неотсортированной выборки, а не 10 самых свежих записей.
Альтернативы: (а) сверить описания только по коду — отклонена, именно из-за кода в спеках появились бы неверные коды 404 и 500; (б) исправить поведение вместе с документацией — отклонена, вышла бы за рамки изменения и потребовала delta-спеки на существующие capability `callback-inspection` и `callback-capture`.

**4. Структура документации — от «что это» к «как использовать» к «если не работает».**
Порядок разделов: название и описание → Features → Quick Start → Docker → Environment Variables → API Reference → Usage Examples → Project Structure → Troubleshooting. Справочник переменных окружения располагается перед справочником API, потому что его значения (`LOCAL_IP`, `PORT`) используются в примерах вызовов.
Альтернатива — справочник API первым: отклонена, читатель не может понять, какие значения подставить в примеры, пока не дошёл до раздела конфигурации.

**5. Примеры `curl` образуют один сквозной сценарий, а не набор разрозненных сниппетов.**
Значение токена из `GET /generate` переиспользуется в последующих командах через shell-переменную, чтобы иллюстрировать реальный порядок работы.
Альтернатива — пример на каждый эндпоинт независимо: отклонена, теряется основной сценарий использования сервиса.

## Risks / Trade-offs

- **Дублирование русского текста увеличивает объём файла и стоимость правок** → русские пояснения формулируются кратко, как дополнение, а не полный перевод; при изменении поведения обновляются обе версии в рамках одной задачи
- **Текст разойдётся с кодом при последующих изменениях** → опорные требования (сверка с `Dockerfile`, `requirements.txt`, `.env.sample`, `app/config.py`) включены в спецификацию как проверяемые сценарии; отдельные требования к точности есть в capability `service-runtime`
- **Описание quirks как штатного поведения закрепит их как ожидаемые** → принято осознанно: capability-спеки уже фиксируют это поведение как текущее, и их изменение оформляется отдельным change
