# Proposal

## Why

`Readme.md` сейчас содержит только голый список команд установки и запуска — без заголовка, описания сервиса, справочника API и пояснений к переменным окружения. Пользователь, попавший в репозиторий, не понимает, что делает Mini Collaborator, какие у него эндпоинты и как их вызывать, поэтому приходится читать исходный код (`app/main.py`) и `.env.sample`. Нужна полноценная документация, которая закрывает вопрос «что это и как этим пользоваться» без чтения кода.

## What Changes

- Переписать `Readme.md` как полноценную документацию проекта вместо списка команд
- Добавить заголовок с названием проекта и краткое описание назначения (приёмник HTTP-коллбэков по токену для последующего анализа)
- Добавить раздел с возможностями сервиса: выдача токена, приём коллбэков, журнал, статистика, автоочистка
- Оформить быстрый старт для Linux/macOS и Windows с сохранением существующих команд
- Добавить раздел запуска через Docker с примером `docker build` / `docker run`
- Добавить справочник переменных окружения с описанием и значениями по умолчанию на основе `.env.sample` и `app/config.py`
- Добавить полный справочник API: `GET /`, `GET /generate`, `ALL /c/{token}`, `GET /logs/{token}`, `GET /tokens`, `GET /stats/{token}`, `DELETE /logs/{token}` — с параметрами, кодами ответа и примерами `curl`
- Добавить раздел со структурой проекта и описанием файлов
- Добавить раздел troubleshooting с типовыми проблемами: занятый порт, незаданный `LOCAL_IP`, контейнер без volume для SQLite, токен не появляется в `/tokens`
- Основной текст документации — на английском, ключевые разделы дублируются или снабжаются русскими пояснениями
- **BREAKING** формат: `Readme.md` перестаёт быть чистым списком команд — команды переходят внутрь структурированных разделов с заголовками и пояснениями

## Capabilities

### New Capabilities

- `project-documentation`: Требования к содержимому, структуре, языку, полноте и актуальности документации проекта в `Readme.md`. Новая capability, потому что требования к документации ранее нигде не были зафиксированы, и без них «документация готова» нечем проверить.

### Modified Capabilities

_(пусто — поведение сервиса не меняется; capability `service-runtime`, `callback-tokens`, `callback-capture`, `callback-inspection`, `data-retention` описывают уже существующее поведение, которое документация лишь отражает, поэтому delta-спеки для них не создаются)_

## Impact

- **Файлы**: `Readme.md` (полная переработка). Остальные файлы проекта не изменяются.
- **Код**: не затрагивается. Изменение только документационное — новых зависимостей, конфигурации и эндпоинтов нет.
- **Спецификации**: существующие capability не изменяются; появляется новая capability `project-documentation` с требованиями к `Readme.md`.
- **Риски**: основной риск — расхождение документации с кодом. Текст сверяется с фактическим поведением запущенного сервиса и с исходным кодом (`app/main.py`, `app/config.py`, `.env.sample`); существующие quirks (невалидируемый токен на `/c/{token}`, 200 + `[]` вместо 404 на `/logs/{token}`, код 404/500 внутри тела вместо HTTP-статуса на `/stats/{token}` и `/c/{token}`) документируются как есть, без «исправлений» в описании.
