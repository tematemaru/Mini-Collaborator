# Spec Delta

## Purpose

Требования к пользовательской документации проекта Mini Collaborator в файле `Readme.md`: какие разделы и сведения она обязана содержать, на каком языке она написана и по каким признакам признаётся актуальной.

## ADDED Requirements

### Requirement: Назначение и возможности сервиса описаны в Readme
`Readme.md` SHALL начинаться с заголовка с названием проекта и содержать краткое описание назначения сервиса — приём HTTP-запросов (коллбэков) по выданному токену с их сохранением для последующего анализа — и перечень его возможностей: выдача токена, приём коллбэков, просмотр журнала, статистика по токену, автоочистка старых записей.

#### Scenario: Читатель понимает назначение сервиса
- **WHEN** пользователь открывает `Readme.md`
- **THEN** по заголовку и первым разделам он понимает, что делает сервис и какие задачи он решает, без чтения исходного кода

#### Scenario: Перечень возможностей присутствует
- **WHEN** пользователь читает `Readme.md`
- **THEN** он видит перечень из пяти возможностей: выдача токена, приём коллбэков, журнал по токену, статистика, автоочистка

### Requirement: Инструкции по установке и запуску сохранены
`Readme.md` SHALL содержать рабочие инструкции по созданию виртуального окружения и его активации отдельно для Linux/macOS и для Windows, установку зависимостей из `requirements.txt`, создание файла `.env` из `.env.sample` и запуск сервиса, а также инструкции по запуску через Docker с командами сборки образа и запуска контейнера с пробросом порта и передачей `.env`.

#### Scenario: Инструкция для Linux/macOS
- **WHEN** пользователь следует разделу быстрого старта для Linux/macOS
- **THEN** он выполняет `python3 -m venv venv`, `source venv/bin/activate`, `pip install -r requirements.txt`, `cp .env.sample .env`, `python run.py` — и команды приведены в правильном порядке

#### Scenario: Инструкция для Windows
- **WHEN** пользователь следует разделу быстрого старта для Windows
- **THEN** он выполняет `python -m venv venv`, `venv\Scripts\activate`, `pip install -r requirements.txt`, `cp .env.sample .env`, `python run.py`

#### Scenario: Запуск через Docker
- **WHEN** пользователь следует разделу Docker
- **THEN** он получает команду сборки образа и команду запуска контейнера с пробросом порта 8000 и передачей файла `.env`

#### Scenario: Команды пригодны для копирования
- **WHEN** пользователь копирует команду из блока кода
- **THEN** она выполняется без необходимости вручную дорабатывать аргументы или расставлять переносы строк

### Requirement: Справочник переменных окружения
`Readme.md` SHALL содержать справочник всех переменных окружения, читаемых сервисом, — `HOST`, `PORT`, `LOCAL_IP`, `DATABASE_URL`, `CLEANUP_HOURS`, `CLEANUP_INTERVAL`, `DEBUG` — с указанием типа значения, его смысла и значения по умолчанию, совпадающего с фактическим значением, применяемым при незаданной переменной.

#### Scenario: Таблица переменных совпадает с кодом
- **WHEN** пользователь сопоставляет таблицу переменных в `Readme.md` с `.env.sample` и `app/config.py`
- **THEN** перечень переменных и значения по умолчанию совпадают с фактическими, включая `LOCAL_IP=127.0.0.1` и `DEBUG=False` по умолчанию

#### Scenario: Переменная не задана
- **WHEN** пользователь не задаёт переменную и полагается на значение по умолчанию
- **THEN** документация сообщает, какое значение будет применено, и что сервис стартует без ошибки

#### Scenario: Специальное значение LOCAL_IP
- **WHEN** пользователь читает описание `LOCAL_IP`
- **THEN** документация поясняет, что значение используется при формировании `callback_url` в `GET /generate`, и предлагает указать реальный IP-адрес машины в локальной сети, а не `127.0.0.1`

### Requirement: Справочник HTTP API
`Readme.md` SHALL содержать справочник всех эндпоинтов сервиса — `GET /`, `GET /generate`, `/c/{token}` для методов `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `GET /tokens`, `GET /logs/{token}`, `GET /stats/{token}`, `DELETE /logs/{token}` — для каждого с указанием пути и методов, параметров пути и query, кодов успешного ответа и кодов ошибок с описанием причины.

#### Scenario: Все эндпоинты задокументированы
- **WHEN** пользователь ищет в `Readme.md` справочник API
- **THEN** он находит записи для всех семи операций сервиса, и ни одна из них не отсутствует

#### Scenario: Параметры пути описаны
- **WHEN** пользователь читает описание эндпоинта, принимающего токен
- **THEN** он понимает, что токен передаётся в пути, и видит пример вызова с конкретным значением токена

#### Scenario: Коды ошибок описаны
- **WHEN** пользователь читает описание эндпоинта
- **THEN** он видит коды ответов с пояснением: `GET /stats/{token}` при отсутствии записей и `/c/{token}` при ошибке сохранения отвечают HTTP 200 с телом вида `[{"error": "<текст>"}, <код>]`, где <код> равен 404 для `/stats/{token}` и 500 для `/c/{token}`; документация поясняет, что числовой код присутствует только внутри тела и не влияет на HTTP-статус ответа

#### Scenario: Фактическое поведение описано без искажений
- **WHEN** пользователь сверяет документацию с поведением сервиса
- **THEN** документация отражает фактическое поведение: `/logs/{token}` для неизвестного токена возвращает 200 с пустым массивом; `/stats/{token}` и `/c/{token}` в ошибочных случаях отвечают 200 с массивом `[{"error": ...}, <код>]`; `/c/{token}` не проверяет существование токена; `/generate` не создаёт запись о токене в базе; в `recent` для `/stats/{token}` входит до 10 записей, взятых из неотсортированной выборки, а не 10 самых свежих

### Requirement: Примеры использования API
`Readme.md` SHALL содержать исполняемые примеры вызовов `curl`, покрывающие полный сценарий работы: получение токена, отправку коллбэка на выданный адрес, чтение журнала и статистики по этому токену, а также удаление журнала.

#### Scenario: Сквозной сценарий в примерах
- **WHEN** пользователь последовательно выполняет примеры `curl` из раздела использования
- **THEN** примеры образуют связную цепочку: значение токена из `GET /generate` используется в последующих вызовах, и каждый пример синтаксически корректен

#### Scenario: Примеры согласованы со справочником
- **WHEN** пользователь сравнивает примеры `curl` с записями в справочнике API
- **THEN** пути, методы и имена возвращаемых полей в примерах совпадают со справочником

### Requirement: Описание структуры проекта
`Readme.md` SHALL содержать раздел со структурой репозитория, перечисляющий ключевые файлы и каталоги с кратким описанием их назначения: точка входа запуска, пакет приложения, файл конфигурации, модели, подключение к базе, зависимости, пример файла окружения, Dockerfile.

#### Scenario: Читатель ориентируется в репозитории
- **WHEN** пользователь читает раздел структуры проекта
- **THEN** он понимает, где находится точка входа, где лежит логика приложения и где задаются настройки

### Requirement: Раздел устранения неполадок
`Readme.md` SHALL содержать раздел troubleshooting с не менее чем четырьмя типовыми проблемами и их решениями: порт `8000` уже занят, `LOCAL_IP` не задан или остался равным `127.0.0.1`, база SQLite не переживает пересоздание контейнера Docker, выданный токен не появляется в `GET /tokens` до первого коллбэка.

#### Scenario: Пользователь диагностирует проблему
- **WHEN** у пользователя возникает одна из перечисленных проблем
- **THEN** он находит её описание и конкретное действие для устранения, а не только упоминание симптома

### Requirement: Язык документации
Основной текст `Readme.md` SHALL быть написан на английском языке, а ключевые разделы — быстрый старт, справочник переменных окружения, справочник API и устранение неполадок — SHALL сопровождаться русскими пояснениями. Имена файлов, переменных окружения, полей JSON, команд и эндпоинтов SHALL приводиться без перевода.

#### Scenario: Ключевые разделы понятны обоим языкам
- **WHEN** читатель открывает любой из ключевых разделов
- **THEN** он находит содержательное пояснение на английском и на русском

#### Scenario: Технические идентификаторы не переведены
- **WHEN** пользователь копирует из документации имя переменной, эндпоинт, имя файла или поле JSON
- **THEN** идентификатор совпадает с используемым в коде, без перевода и искажения

### Requirement: Актуальность документации
Содержание `Readme.md` SHALL соответствовать фактическому поведению сервиса на момент его написания: командам в `Dockerfile`, зависимостям из `requirements.txt`, переменным из `.env.sample`, значениям по умолчанию из `app/config.py` и эндпоинтам, объявленным в приложении.

#### Scenario: Сверка документации с кодом
- **WHEN** выполняется проверка документации на соответствие коду
- **THEN** ни одна команда из `Readme.md` не ссылается на отсутствующий файл, не использует отсутствующую зависимость и не вызывает несуществующий эндпоинт

#### Scenario: Существующие команды не потеряны
- **WHEN** пользователь сравнивает новый `Readme.md` с прежней версией
- **THEN** все ранее приведённые команды (создание venv, активация, установка зависимостей, копирование `.env`, `python run.py`, `docker build`, `docker run`) присутствуют в новой версии

#### Scenario: Markdown корректен
- **WHEN** `Readme.md` открывается в Markdown-рендерере или проверяется линтером
- **THEN** разметка корректна: заголовки имеют иерархию, блоки кодв размечены как fenced-блоки с указанием языка, таблицы отображаются таблицами
