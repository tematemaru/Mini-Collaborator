# service-runtime Specification

## Purpose
Runtime-конфигурация и базовая диагностика HTTP-сервиса Mini Collaborator: чтение настроек из окружения, запуск ASGI-приложения и проверка его доступности.

## Requirements

### Requirement: Загрузка конфигурации из окружения
Сервис SHALL читать все параметры конфигурации из переменных окружения (с поддержкой файла `.env`) и использовать значения по умолчанию, если переменная не задана: `HOST=0.0.0.0`, `PORT=8000`, `LOCAL_IP=127.0.0.1`, `DATABASE_URL=sqlite:///callbacks.db`, `CLEANUP_HOURS=24`, `CLEANUP_INTERVAL=3600`, `DEBUG=False`.

#### Scenario: Переменные окружения заданы
- **WHEN** процесс стартует с установленными `HOST`, `PORT`, `LOCAL_IP`, `DATABASE_URL`, `CLEANUP_HOURS`, `CLEANUP_INTERVAL`, `DEBUG`
- **THEN** сервис использует именно эти значения для всех операций

#### Scenario: Переменная окружения отсутствует
- **WHEN** переменная окружения не задана
- **THEN** сервис использует соответствующее значение по умолчанию, не завершаясь с ошибкой

#### Scenario: Числовые параметры заданы некорректно
- **WHEN** `PORT`, `CLEANUP_HOURS` или `CLEANUP_INTERVAL` содержат значение, не convertible в целое число
- **THEN** сервис падает на этапе загрузки конфигурации, не поднимая HTTP-сервер

### Requirement: Инициализация схемы хранилища при старте
Сервис SHALL создавать таблицы, описанные метаданными ORM (таблица `callbacks`), до начала приёма запросов.

#### Scenario: Первый запуск на пустой базе
- **WHEN** сервис стартует и таблица `callbacks` отсутствует в `DATABASE_URL`
- **THEN** таблица создаётся автоматически до обработки первого запроса

#### Scenario: Таблица уже существует
- **WHEN** сервис стартует, а таблица `callbacks` уже присутствует
- **THEN** сервис запускается без изменения существующих данных

### Requirement: Диагностический эндпоинт корня
Сервис SHALL отдавать по `GET /` HTTP 200 с JSON-объектом, содержащим `status` со значением `"ok"`, `service` со значением `"Mini Collaborator"`, `version` и `server_ip`, равным `LOCAL_IP` из конфигурации.

#### Scenario: Проверка доступности сервиса
- **WHEN** клиент выполняет `GET /`
- **THEN** сервис отвечает HTTP 200 и телом `{"status": "ok", "service": "Mini Collaborator", "version": <version>, "server_ip": <LOCAL_IP>}`

#### Scenario: Публичность эндпоинта
- **WHEN** клиент выполняет `GET /` без токена и без аутентификации
- **THEN** сервис обрабатывает запрос, не требуя учётных данных

### Requirement: Запуск ASGI-сервера
Сервис SHALL запускаться как ASGI-приложение (uvicorn) на `HOST` и `PORT` из конфигурации, с автоперезагрузкой и уровнем логирования `debug` при `DEBUG=True` и без автоперезагрузки с уровнем `info` при `DEBUG=False`.

#### Scenario: Продуктовый режим
- **WHEN** сервис запускается с `DEBUG=False`
- **THEN** сервер слушает `HOST:PORT` без автоперезагрузки и логирует на уровне `info`

#### Scenario: Режим отладки
- **WHEN** сервис запускается с `DEBUG=True`
- **THEN** сервер включает автоперезагрузку, логирует на уровне `debug` и включает SQL-трассировку движка базы данных

#### Scenario: Запуск файла приложения как точки входа с перезагрузкой
- **WHEN** сервис запускается прямым исполнением файла приложения при `DEBUG=True` (автоперезагрузка включена), и uvicorn импортирует этот файл как модуль `app.main`
- **THEN** блок запуска внутри `if __name__ == "__main__"` не выполняется при импорте, рекурсивный перезапуск процесса не происходит, а сервер продолжает работать с параметрами из `HOST`, `PORT`, `DEBUG`
