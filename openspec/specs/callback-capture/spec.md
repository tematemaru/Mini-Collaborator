# callback-capture Specification

## Purpose
Приём и сохранение входящих HTTP-запросов (коллбэков) по токену: сервис выступает приёмником, который фиксирует всё, что прислал внешний сервис, для последующего анализа.

## Requirements

### Requirement: Приём коллбэка по токену
Сервис SHALL принимать запросы к пути `/c/{token}` методами `GET`, `POST`, `PUT`, `DELETE` и `PATCH`, сохранять их и отвечать HTTP 200 с телом `{"status": "received", "token": <token>, "timestamp": <ISO 8601 UTC>}`.

#### Scenario: Успешная запись коллбэка
- **WHEN** клиент выполняет любой из поддерживаемых методов по пути `/c/{token}`
- **THEN** сервис сохраняет запрос и отвечает HTTP 200 с `status` = `"received"`, `token` = значением из пути и `timestamp` в ISO 8601

#### Scenario: Поддерживаемые методы
- **WHEN** клиент выполняет `GET`, `POST`, `PUT`, `DELETE` или `PATCH` по `/c/{token}`
- **THEN** запрос обрабатывается одинаково; методы вне этого списка не обслуживаются данным путём

#### Scenario: Неизвестный токен
- **WHEN** клиент отправляет коллбэк с токеном, для которого ранее не было вызвано `GET /generate`
- **THEN** сервис всё равно принимает и сохраняет коллбэк, не проверяя существование токена

### Requirement: Сохранение содержимого запроса
Сервис SHALL сохранять для каждого коллбэка: токен, IP-адрес клиента (значение `"unknown"`, если клиент недоступен), HTTP-метод, все заголовки запроса в виде JSON-объекта, все query-параметры в виде JSON-объекта и тело запроса как строку, декодированную с игнорированием ошибок, в записи с меткой времени создания (UTC).

#### Scenario: Коллбэк с телом
- **WHEN** клиент отправляет `POST /c/{token}` с JSON-телом и query-параметрами
- **THEN** сервис сохраняет тело как строку, query-параметры как JSON-объект и заголовки как JSON-объект той же структуры, что и исходный запрос

#### Scenario: Бинарное или невалидное по кодировке тело
- **WHEN** тело запроса не декодируется в UTF-8
- **THEN** сервис сохраняет тело с игнорированием ошибок декодирования и не отклоняет запрос

#### Scenario: Запрос без тела
- **WHEN** клиент отправляет `GET /c/{token}` без тела
- **THEN** сервис сохраняет запись с пустым телом

### Requirement: Ошибка сохранения коллбэка
Сервис SHALL отвечать HTTP 500 с телом `{"error": "<сообщение об ошибке>"}`, если во время чтения тела или сохранения в базу возникло исключение.

#### Scenario: Недоступна база данных
- **WHEN** сохранение коллбэка завершается исключением
- **THEN** сервис отвечает HTTP 500 с полем `error`, содержащим текст исключения
