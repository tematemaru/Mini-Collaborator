# callback-inspection Specification

## Purpose
Чтение накопленных коллбэков: журнал запросов по токену, агрегированная статистика и удаление записей. Нужен, чтобы после передачи `callback_url` внешнему сервису можно было разобраться, что он прислал.

## Requirements

### Requirement: Просмотр журнала по токену
Сервис SHALL отдавать по `GET /logs/{token}` HTTP 200 с JSON-массивом записей, отсортированных по времени создания от новых к старым, где каждая запись содержит `id`, `ip`, `method`, `headers` (объект), `query` (объект), `body` (строка) и `created_at` в ISO 8601.

#### Scenario: Журнал содержит записи
- **WHEN** в базе есть несколько коллбэков по токену `abc` с разными `created_at`
- **THEN** сервис отвечает HTTP 200 массивом записей, упорядоченным по убыванию `created_at`

#### Scenario: Записей по токену нет
- **WHEN** в базе нет коллбэков по запрошенному токену
- **THEN** сервис отвечает HTTP 200 с пустым массивом, без ошибки 404

#### Scenario: Заголовки и query возвращаются как объекты
- **WHEN** клиент запрашивает журнал по токену
- **THEN** поля `headers` и `query` в ответе являются JSON-объектами, а не строками с JSON внутри

### Requirement: Статистика по токену
Сервис SHALL отдавать по `GET /stats/{token}` HTTP 200 с объектом, содержащим `total` (число коллбэков), `unique_ips`, `methods` (количество коллбэков по каждому HTTP-методу), `first_request` и `last_request` (ISO 8601 UTC), а также `recent` — не более 10 последних записей с полями `time`, `method`, `ip`.

#### Scenario: Статистика по существующему токену
- **WHEN** в базе есть коллбэки по токену `abc`
- **THEN** сервис отвечает HTTP 200, где `total` равно числу записей, `unique_ips` — числу различных IP, `methods` — распределению коллбэков по методам, `first_request` и `last_request` — границам по времени

#### Scenario: Токен не найден
- **WHEN** в базе нет коллбэков по запрошенному токену
- **THEN** сервис отвечает HTTP 404 с телом `{"error": "Token not found"}`

#### Scenario: Ограничение размера выборки `recent`
- **WHEN** по токену накоплено более 10 коллбэков
- **THEN** поле `recent` содержит не более 10 элементов, каждый с полями `time`, `method`, `ip`

### Requirement: Удаление журнала по токену
Сервис SHALL удалять все записи коллбэков по указанному токену по запросу `DELETE /logs/{token}` и отвечать HTTP 200 с объектом `{"deleted": <число удалённых записей>, "token": <token>}`.

#### Scenario: Удаление существующих записей
- **WHEN** клиент выполняет `DELETE /logs/{token}`, и по токену есть 3 записи
- **THEN** сервис удаляет все 3 записи и отвечает HTTP 200 с `deleted` = 3

#### Scenario: Удаление при отсутствии записей
- **WHEN** клиент выполняет `DELETE /logs/{token}`, и по токену нет ни одной записи
- **THEN** сервис отвечает HTTP 200 с `deleted` = 0, без ошибки 404

#### Scenario: Данные других токенов не затрагиваются
- **WHEN** клиент выполняет `DELETE /logs/{token}` при наличии записей по другим токенам
- **THEN** записи по другим токенам остаются в базе и остаются доступными через `GET /logs/{other}`
