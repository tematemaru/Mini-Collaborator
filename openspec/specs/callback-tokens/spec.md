# callback-tokens Specification

## Purpose
Выдача и перечисление токенов коллбэков — идентификаторов, по которым внешние системы отправляют запросы сервису, чтобы их можно было потом найти и проанализировать.

## Requirements

### Requirement: Генерация токена коллбэка
Сервис SHALL отдавать по `GET /generate` HTTP 200 с новым уникальным токеном (UUID4) и производными данными для вызова коллбэка: `callback_url` вида `http://<LOCAL_IP>:<PORT>/c/<token>`, `dns` вида `<token>.collab.local` и `created_at` в ISO 8601 (UTC).

#### Scenario: Запрос нового токена
- **WHEN** клиент выполняет `GET /generate`
- **THEN** сервис отвечает HTTP 200 с полями `token` (уникальный UUID4), `callback_url`, `dns`, `created_at`

#### Scenario: Уникальность выданных токенов
- **WHEN** клиент выполняет `GET /generate` несколько раз
- **THEN** каждый вызов возвращает новый токен, отличный от ранее выданных

#### Scenario: Токен использует адрес из конфигурации
- **WHEN** клиент выполняет `GET /generate`
- **THEN** `callback_url` содержит `LOCAL_IP` и `PORT` из конфигурации, а не адрес хоста, по которому пришёл запрос

#### Scenario: Токен не сохраняется в хранилище
- **WHEN** клиент выполняет `GET /generate`
- **THEN** сервис не создаёт запись о токене в базе данных — токен появляется в перечне токенов только после приёма хотя бы одного коллбэка с ним

### Requirement: Перечисление токенов с активностью
Сервис SHALL отдавать по `GET /tokens` HTTP 200 с объектом `{"tokens": [...]}`, содержащим уникальные значения токенов, для которых в базе есть хотя бы одна запись коллбэка.

#### Scenario: В базе есть записи
- **WHEN** в базе есть коллбэки с токенами `abc` и `def`, причём `abc` встречается несколько раз
- **THEN** сервис отвечает HTTP 200 и списком токенов, где `abc` присутствует один раз

#### Scenario: База пуста
- **WHEN** в базе нет ни одной записи коллбэка
- **THEN** сервис отвечает HTTP 200 с пустым списком токенов, без ошибки 404
